## 원인

세 문항 모두 질문 분해(하위 질문 2개)를 탔고, 하위 질문이 원 질문의 주어나 조건을 잃었다(`sub_queries_holdout.txt`).

| 문항 | 원 질문에 있고 하위 질문에서 빠진 것 | 첫 정답이 문맥에 든 자리(1·2·3회) | 문맥 기준 재현율 |
|---|---|---|---|
| 101 | "한국에서 일하는 팀원"(미국 밖 근무 조건). 3회 모두 빠짐 | 7, 7, 7 | 0.5 (미국 밖 팀원의 영수증 규정 청크는 3회 모두 문맥에 없음) |
| 106 | "지원팀 온보딩 버디"(누구의 일인지). 3회 모두 빠짐 | 3, 3, 5 (둘째 정답은 3회 모두 8번째) | 1.0 |
| 109 | "데이터팀"이 1회차 첫 하위 질문, 2회차 두 하위 질문에서 빠짐. 3회차는 두 하위 질문 모두 유지 | 7, 5, 8 | 1.0 |

- 주어·조건을 지킨 분해 문항(104, 105, 108, 110)은 3회 모두 Recall@5 1.0이다.
- 달러 금액이 없는 나뉜 질문의 첫 검색은 k=8이고, 원 질문 문장의 후보 목록은 끝 1자리(`FULL_TAIL = 1`, `backend/rag/retrieve/search.py`, 사전 등록 62.38)만 받는다. 나머지 7자리는 하위 질문 목록과 링크 확장이 채운다. 그래서 하위 질문이 조건을 잃으면 원 질문으로만 가까운 청크는 상위 5 안에 들기 어렵다. 106번 둘째 정답과 109번 3회차 첫 정답은 8번째(마지막) 자리에 들어왔다.
- 109번 3회차는 하위 질문이 "데이터팀"을 지켰는데도 첫 정답이 8번째라, 109번은 주어 소실만으로 설명되지 않는다.
- 문맥 기준 재현율이 0.950인 것은 8자리와 같은 쪽 채우기(`page_fill`)로 정답 근거 대부분이 결국 문맥에 들어오기 때문이다. 빠진 것은 101번 첫째 정답(3회 모두)뿐이다.

## 표본 크기
