방법: 저장소 코드(main d01eaff)를 복사본에서 평가셋에 적용하고 저장된 운영 측정 결과만 다시 읽음. LLM·임베딩·운영·Langfuse 호출 없음. 문항별 전체 표는 out/tables.md, out/result.json, 통계는 out/stats.txt.

## 1. 결론
1. 두 변경이 닿는 문항은 겹치지 않는다(확정). v2 50, 검증 20, 새 문항 5건(75문항)은 물음이 아닌 앞 문장이 없어 62.45가 닿지 않고, 금액 5문항은 달러 금액이 있어 62.44(`split_k`)가 닿지 않는다. 합동 검토 질문 모음 2건만 둘 다 닿을 수 있으나 00047 묶음에서 재지 않았다.
2. 그래서 묶음별 단독 비교가 이미 성립한다. v2·검증·새 문항의 00044→00047 변화는 62.44 또는 회차 변동, 금액 00046→00047 변화는 62.45 또는 회차 변동. 00044→00046 사이 답 경로 변경은 62.43(달러 질문만)뿐, 00046→00047은 62.44·62.45뿐(git diff 확인).
3. v2 정답 근거 0.9133→0.9422(+0.0289)는 전부 62.44가 닿는 넓힌 16문항에서 나왔다(넓히지 않은 9문항은 바뀐 문항 0). 3번 +0.0200, 6번 +0.0200은 62.44 효과(같은 첫 문맥에서 넓힌 자리 인용 6행→0행, 0/6→6/6, Fisher p=0.0022). 39번 -0.0044는 62.44의 대가(넓힌 자리에만 있던 정답 둘째 위치를 잃음, 강한 추정, 사전 등록 위험 (5)와 같은 방향). 38번 -0.0067은 검색 변동이 섞여 가르지 못함.
4. 검증 0.8667→0.8333(-0.0333)은 101번 3회차 거절(-0.0167, ground/unsupported)과 104번(-0.0167). 62.45와 무관(확정). 두 실패 모양은 62.44 이전 리비전에도 같은 문맥에서 있었다(101번 거절 이전 네 리비전 3/12 대 00047 1/3, p=1.000; 104번 같은 문맥·같은 오답 청크가 00044 3회차에 있음, 3/12 대 2/3, p=0.242). 62.44가 빈도를 올렸는지는 0원으로 못 가름. 105번·108번은 변화 없음(108번은 00032부터 15행 같음). 109번은 62.44 방향 개선(추정).
5. 금액 14→13은 62.44와 무관(확정). 62.45 때문이라는 근거는 없고 회차 변동 범위(추정). 바뀐 행: 202번 2회차 답→거절, 204번 1회차 답→거절, 204번 3회차 거절→답(모두 ground/unsupported 경로). 202번·204번은 62.45 이전 리비전에서도 같은 단계로 거절(62.45 없던 일곱 리비전 105행 중 거절 20행). 거절 1/15→2/15 p=1.000, 재검색 행 3/15→0/15 p=0.224, 10초 초과 행 8/15→4/15 p=0.264.
6. "가르기"에 추가 측정은 필요 없다. 남은 한계는 문항당 3회라는 표본 크기. 일반화되는 수정으로 확정해 권할 것은 없음(가설: 답 고르기에서 판정 구절 청크와 인용이 더 많이 겹치는 후보를 먼저 고르기, 효과 미확인).
