# 청크 파일과 색인의 판 날짜 하루 차이 원인 확인 (2026-11-16)

- 날짜: 2026-11-16
- 기준 커밋: origin/main `eb8c9aac`
- 비용: 0원. 네트워크 없음. 로컬 파일과 로컬 핸드북 캐시(`~/.cache/provena/handbook`, 수집기 기본 경로, HEAD `129243bcffcf` = 고정 커밋, 얕은 이력)만 읽음.
- 대상: `EVAL_REPORT.md` 5장 한계 목록의 "`data/chunks/chunks.jsonl`과 `data/index/chunks.jsonl`은 `version_date`가 23,095줄 중 1,005줄(68개 판)에서 하루 다르다 … 원인은 확인하지 못했고 다음은 추정이다" 문장.

## 방법 (`t5_vdate.py`)

1. 두 파일을 `chunk_id`로 맞춰 `version_date`가 다른 줄을 찾고, 다른 칸도 다른지 본다.
2. 판 날짜는 `version_id`(판 커밋 sha 앞 12자리)의 커밋 시각에서 나온다(`backend/rag/ingest/handbook.py`). 불일치 줄의 `version_id`마다 로컬 캐시에서 `git show -s --format="%H %ct %cs %ci"`를 읽어 두 방식의 날짜를 만든다.
   - 고친 뒤 방식(커밋 d259169, `utc_day`): 커밋 시각 `%ct`를 UTC 날짜로 바꾼 값
   - 고치기 전 방식: 커밋한 사람 시간대의 날짜 `%cs`
3. 대조군: 두 파일의 날짜가 같은 판 592개에서도 두 방식의 날짜가 다른 판이 있는지 센다.

결론(확정): 색인 `data/index/chunks.jsonl`의 1,005줄은 고치기 전 방식(`%cs`)의 판 날짜를, 청크 파일 `data/chunks/chunks.jsonl`은 고친 뒤 방식(UTC 날짜)의 판 날짜를 갖고 있다. 두 방식의 날짜가 다른 판(커밋한 사람 시간대가 UTC와 달라 날짜가 넘어간 커밋)에서만 차이가 나고, 두 방식이 같은 판에서는 차이가 없다. 예: 판 커밋 `04a7b782c384`(2026-07-30 18:18:10 -0700)는 `%cs` 2026-07-30, UTC 2026-07-31이고 색인이 07-30, 청크 파일이 07-31이다. 색인을 만들 때 쓴 수집 결과가 d259169 이전 방식으로 만든 것이라는 추정이 커밋별 날짜로 맞는다.
