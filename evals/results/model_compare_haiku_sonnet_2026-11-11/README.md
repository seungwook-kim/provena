# Haiku 5.5 대 Sonnet 5.5 답 작성 모델 비교 (2026-11-11)

`EVAL_REPORT.md` 8장 "모델과 구성을 고른 이유" 표의 답 작성 LLM 행이 기대는 원자료입니다. 같은 공급자(Anthropic)의 두 모델을 같은 평가셋에 한 번씩 돌린 로컬 측정이며, 운영 배포판 측정이 아닙니다.

## 조건

- 측정일: 2026-11-11 밤(21~22시, 한국 시간). 저장소 브랜치 `seunguk`, HEAD `9c71e0a` 위에 커밋하지 않은 수정이 있는 작업 트리에서 돌렸고, 이 측정은 저장소 파일을 고치지 않았다.
- 평가셋: `evals/dataset_v2.jsonl`(sha256 `810d01f1c27dd5475f98fb771fcd821df377c360c4aa6e6c15f7b2f316524d9f`)의 관련 25건(id 1~15, 31~40번), 각 1회. 서비스 경로와 같은 단일 그래프.
- 실행기: `python -m evals.agent.exp_multi_v2 run --store pg --llm anthropic --arms single`에 서비스 설정 인자를 붙였다. 검색 저장소는 로컬 DB(23,095청크)이며 운영 DB는 읽거나 쓰지 않았다. summary 파일의 `service_path` 문구에 적힌 "운영 DB(PgStore)"는 평가 실행기의 고정 문구이고 이번 측정에서 쓴 DB는 로컬 DB다.
- **모델을 바꾼 범위: 전체 교체.** 서비스는 질문 분류, 질문 분해, 판정, 답 작성(빠른 답 포함), 근거 확인, 검색어 번역에 같은 모델 설정(`LLM_MODEL`) 하나를 쓰고, 단계별로 모델을 지정하는 기능이 없다. 그래서 두 실행은 모델 이름 하나만 다르다(`claude-haiku-5-5` 대 `claude-sonnet-5-5`). 호출 기록(`llm_trace`)의 모델은 실행마다 한 가지뿐이다. 번역 저장소는 모델 이름을 키로 쓰므로 Haiku 실행은 기존 Haiku 번역 일부를 재사용했을 수 있고 Sonnet은 새로 번역했다.
- Sonnet 실행에서만 서비스 설정과 다르게 한 것 세 가지:
  1. Sonnet 5.5는 `thinking: {"type": "disabled"}` 요청을 400 오류로 거부하고 `{"type": "between_tools"}`를 요구했다. 측정 래퍼가 요청 본문의 이 값만 바꿨다. 추론을 끄려는 설정(`LLM_EFFORT=none`)의 의도는 같다.
  2. 문항당 비용 상한(`LLM_COST_CAP_USD`)의 기본값 0.05달러로는 Sonnet이 첫 문항에서 걸려, Sonnet 실행에서만 1.0달러로 올렸다.
  3. 첫 실행이 37번에서 임베딩 API 연결 오류로 중단돼 37~40번만 이어서 돌렸다. 중단된 37번 행은 버리고 이어서 돌린 행을 썼으며, 1~36번은 중단 전 같은 실행의 행이다. `sonnet_rows.jsonl`은 이렇게 합친 25행(오류 0)이다.
- 두 모델의 summary 파일은 모두 `partial: true`(문항 id를 지정한 실행)이다.

## 결과 (관련 25건, 각 1회)

| 항목 | Haiku 5.5 | Sonnet 5.5 |
|---|---|---|
| 답함 / 거절·되묻기 | 24 / 1 | 24 / 1 |
| 정답 근거 인용률 | 0.887 | 0.887 |
| 인용 정확도 | 0.931 | 0.938 |
| 정답 밖 인용이 있는 문항(답한 24건 중) | 3 | 2 |
| 가짜 인용 위험 문항 | 0 | 0 |
| 정답 위치를 모두 찾고 밖 인용이 없는 문항 | 20 / 25 | 21 / 25 |
| 응답 시간 p50 / p95 | 7.335초 / 9.776초 | 8.326초 / 14.527초 |
| 문항당 비용(기존 비용 집계) | 0.0093달러 | 0.1711달러 |

- 문항별로 달라진 것은 6개(1, 6, 35, 37, 38, 40번)다. Sonnet이 나은 문항은 6번(정답 위치 1/2에서 2/2)이고, 나쁜 문항은 38번(정답 위치 1/2에서 0/2)이다. 나머지는 정답 위치 수가 같고 인용 개수만 다르다.
- 비용은 Sonnet이 Haiku의 18.4배다. 단가표는 두 모델 모두 입력과 출력이 20배 차이이고, Sonnet의 출력 토큰이 30% 적어 18.4배가 됐다. 단가표의 Sonnet 값은 PRD 표에 없어 Claude Code CLI 보고 비용에서 역산한 참고용이라고 단가표에 적혀 있다.
- 비용 집계는 응답이 온 호출만 센다. 응답이 늦을 때 같은 요청을 하나 더 보내는 중복 요청(hedge)의 버려진 쪽은 집계에 없고, 공급자가 청구할 수 있다. 실제 청구액은 공급자 콘솔 사용량으로 확인해야 한다.
