# 사전 등록 메모: 멀티 그래프 하위 에이전트 체크포인트 끄기 (2026-11-17 17:25 KST, 코드 수정·측정 전 작성)

이 메모는 `evals/PREREGISTER.md` 본표와 별도로, 코드를 고치고 재측정하기 **전에** 기대값과 멈춤 규칙을 적어 둔 것이다. 이 파일만 담은 커밋을 먼저 올린다. 본표 번호는 본표를 고치는 쪽에서 붙인다(가번호 62.92).

## 배경

- 체크포인트 코멘트 4-1: 검증 v2 20건의 답을 낸 질문 p95가 운영 판 `provena-api-00205-zit`(커밋 `e822fb1e`, 멀티 그래프)에서 3회 모두 10초를 넘는다(9.670은 1회차, 10.154, 10.176초).
- 저장된 측정 기록의 0원 분석(Langfuse 구간 시각): 멀티 그래프는 답을 낸 요청마다 단일 그래프보다 약 0.22초를 노드 밖에서 더 쓴다(노드 밖 시간 평균 멀티 0.293초, 단일 0.065~0.074초). 이 시간은 하위 에이전트(검색·작성·검증) 앞뒤에 있다. 하위 에이전트가 바깥 그래프의 Postgres 체크포인터를 물려받아 자기 단계 체크포인트를 하위 이름공간에 따로 쓰는 것이 원인으로 추정된다. DB 호출 수는 아직 직접 세지 않았다.

## 바꿀 것 (하나)

- `backend/graph/multi.py`의 `build_agents`에서 하위 에이전트 중 검색(retriever), 작성(writer), 검증(verifier), 결정표(decision)를 체크포인터 없이 컴파일한다(`compile(checkpointer=False)`). 하위 이름공간 체크포인트만 남지 않고, 에이전트가 돌려주는 상태 칸과 바깥 그래프 체크포인트는 같다.
- 합동 검토(review)는 사람 승인 interrupt와 `Command(resume=...)` 재개가 있어 바꾸지 않는다.
- 코드 수정 전 확인: 위 네 에이전트 안의 노드가 interrupt, 재개, 자기 체크포인트 상태 읽기를 쓰는지 먼저 찾는다. 쓰는 에이전트는 빼고, 안전하게 적용할 수 없으면 코드를 고치지 않고 이 사실만 기록한다.
- 서비스 스위치는 두지 않는다(되돌리기는 직전 운영 판 00205-zit를 그대로 서비스하는 것). 다른 서비스 값은 바꾸지 않는다.

- 기대: 하위 이름공간(`checkpoint_ns`가 빈 값이 아닌 것) 쓰기와 읽기가 0이 된다. 바깥 이름공간(`checkpoint_ns=''`)의 쓰기 횟수와 마지막 상태(결과 종류, 답, 인용)는 바꾸기 전과 같다.
