# 사전 등록: 갈린 판정 두 표의 셋째 표 대기 상한 (`GRAPH_SPLIT_VOTE_WAIT_S`) (2026-11-17, 유료 재측정 전 작성)

이 문서는 유료 재측정을 하기 전에 고정한다. 결과를 본 뒤 상한 값, 지표, 멈춤 규칙을 바꾸지 않는다. `evals/PREREGISTER.md`에 합칠 때 번호를 정한다.

## 바꾸는 것 (하나)

- 환경 변수 `GRAPH_SPLIT_VOTE_WAIT_S`(코드 기본 빈 값 = 지금 동작). 값이 있으면 근거 충분 판정 다수결에서 먼저 온 두 표가 충분과 일부로 갈렸을 때 셋째 표를 그 초까지만 기다린다. 오지 않으면 두 표로 확정하고(같은 수일 때 먼저 온 표를 쓰는 기존 `merge_votes` 규칙), 기록에 `how="split_capped"`를 남긴다.
- 근거 없음 표가 섞인 갈림은 대상이 아니다(결정 0100의 재검색·거절 경로 그대로). 같은 결론 두 표, 근거 없음 두 표(`GRAPH_NONE_VOTE_WAIT_S`), 상한 안에 온 셋째 표는 지금과 같다.
- 측정 값: 1.0초. 코드: `backend/graph/build.py`(`voted`, `two_split`, `vote_log`), `backend/graph/answer_fixes.py`(`split_vote_wait_s`). 시험: `tests/test_split_vote_wait.py`.

## 측정 방법

- 대상: 이 코드를 담은 이미지에 `GRAPH_SPLIT_VOTE_WAIT_S=1.0`만 더한 트래픽 0% 태그 판. 비교 기준은 같은 이미지의 값 없는 판(또는 직전 운영 판과 판정 경로 코드가 같음을 diff로 확인한 판).
- 평가셋: 검증 v2 20건 3회, v2 50건 1회(`evals.latency.deploy_latency`, `evals.latency.deploy_citation_gold`). 예상 비용은 00172 기준 요청당 0.0072달러로 약 0.43달러 + 0.25달러.
- 보고 값: 회차별·3회 합 답을 낸 문항 p95, 판정 표 구성(`judge_votes`의 `how`별 수, `split_capped` 수), 결과 종류(답·되묻기·거절), 인용 정확도, 정답 근거 인용률, 오답 근거 행 수, 과잉 거절, 올바른 거절.

## 멈춤·되돌림 규칙 (측정 전에 정함)

- 측정 중 5xx가 생기거나 DB 연결 수가 감시 기준을 넘어 내려오지 않으면 그 회차를 멈추고 다시 재지 않은 채 기록한다.
- 다음 가운데 하나라도 생기면 이 값을 서비스 설정에 넣지 않고 빈 값으로 둔다.
  - v2 50건에서 결과 종류가 기준 판과 다른 문항이 회차 사이 흔들림 밖으로 생김(같은 문항이 기준 판 여러 회차에서 한 번도 그 종류가 아니었음)
  - v2 50건 인용 정확도 또는 정답 근거 인용률이 기준 판보다 0.02 넘게 낮음
  - 오답 근거 행 수가 기준 판보다 늚
  - 과잉 거절이 0을 넘거나 올바른 거절이 1.000 아래로 내려감
- `split_capped`가 0건이면 시간 효과를 확인하지 못한 것으로 적고, 값을 넣을지는 결정 사항으로 남긴다.
- 비용이 1달러를 넘을 것으로 보이면 v2 50건을 빼고 검증 v2 20건 3회만 재고 그렇게 적는다.
