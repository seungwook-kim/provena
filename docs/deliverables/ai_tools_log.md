## 도구에게 일을 시킬 때 지킨 규칙

(예: Spec을 `docs/specs/`에 먼저 쓰고 시켰다, Out of Scope를 적었다, 테스트 통과 없이 완료라고 받아들이지 않았다)

**박진형**
- Spec(`docs/specs/`)을 먼저 쓰고 구현을 시켰다. 수집·파싱·청킹·검색 모두 Spec 커밋이 첫 구현 커밋보다 앞선다(PR #5·#11·#23·#35).
- 테스트 통과만으로 완료라고 받아들이지 않았다. 핵심 코드를 일부러 깨서 테스트가 실패하는지 확인했다(PR #5·#18·#23·#35).
- 내 PC에서 통과한 것은 증거로 치지 않았다. 팀 CI와 같은 Docker Python 3.12에서 커밋될 파일만으로 다시 돌렸다(PR #23·#35).
- 측정은 기대를 먼저 적고 했다(파서 비교 사전 등록, PR #11).
- 파싱·청킹 결과는 원본과 코드로 대조했다(1,564쪽 git 원본 바이트 대조, 2023 권한표 363칸, PR #7·#13).

## 가장 크게 틀렸던 사례 1개

(무엇을 시켰고, 어떻게 틀렸고, 어떻게 알아챘는가)

**박진형**: 조장의 1차 비교(동결본 재채점, PR #33)를 `search()`로 재현하라고 시켰더니, AI가 평균 점수(Recall@5·MRR)가 같다며 "재현됐다"고 보고했다. 문항별 상위 5개를 동결본과 하나씩 대조하니 하이브리드 30문항 중 16개가 달랐다. 원인은 질문 영어 번역이 달랐던 것(30문항 중 29개)이었고, 조장 번역 장부를 쓰자 30/30이 일치했다(PR #35). 평균이 같아도 문항마다 다른 결과일 수 있다는 것을 배웠고, 이후 재현은 문항별로 대조한다.

**김승욱**: 변이 확인에서 문장 제거 뒤 인용 재검사 조건을 항상 거짓으로 바꿔도 시험이 모두 통과했다. 문장 제거 시험이 거절과 유지 결과만 단언하고, 남은 답에 인용 표시가 하나도 없는 경우는 확인하지 않았기 때문이다. 표시 없는 문장만 남는 답을 거절하는 시험을 더하고 같은 변이로 실패하는 것을 확인했다. 수정의 효과는 같은 조건 3회에서도 정답 근거 인용률이 최대 0.133(15문항 환산 2문항) 흔들리는 것을 출발 버전 반복에서 확인한 뒤, 3회 평균과 범위로만 판단하기로 정하고 모든 수정에 같은 규칙을 적용했다.
