## 3. 원인을 어떻게 찾았나

**방법.** 행 칸과 사전 등록 기록으로만 원인을 말했고, 확인하지 못한 것은 "원인 확인 못 함"으로 적었습니다.
1. 먼저 측정 도구를 의심해 정답 위치 규칙과 채점 값이 일치하는지 봤습니다. 판정한 `gold_total`이 모든 첫 측정, 최종, 검증, v1 행의 값과 같았고, 평가셋의 CRLF 줄바꿈이 해시를 바꾼다는 점도 확인했습니다(`.gitattributes`로 고정).
2. 행의 `retrieved`(답 단계로 넘어간 청크)에 정답 절이 있는지로 검색 실패와 판정·작성·인용 실패를 나눴습니다.
3. 문맥에 없으면 `sub_queries`(질문 분해)와 검색 순위를 봤습니다. 문맥에 있는데 인용이 빠졌으면 `result`, `refuse_stage`, `judge_reason`, `cited`를 봤습니다.
