## 내가 내린 판단과 그 이유

- 인증 실패 응답과 비밀번호 검증을 인증 모듈·테스트 계약으로 묶어 계정 존재 여부 노출을 줄이고, JWT에 폐기 식별자를 넣어 로그아웃 뒤 토큰 재사용을 차단했습니다. 운영 PostgreSQL 경로의 실제 로그인 검증은 별도 확인 사항입니다.
- 브라우저 인증은 HttpOnly 세션 쿠키와 서명된 CSRF double-submit 토큰을 사용하고, 상태 변경 요청에 CSRF를 요구하도록 연결했습니다.
- Google OAuth는 PKCE·state·nonce·ID 토큰 검증을 거치며, 신규 계정은 승인 대기 신청으로 두고 기존 계정 연결 시 role·is_active를 유지하도록 구현했습니다. 실제 Google 브라우저 왕복과 운영 DB 전체 마이그레이션 적용은 확인하지 않았습니다.
- 이메일 인증 기반 회원가입과 인증번호 확인 후 승인되는 흐름을 구현했습니다. 리뷰 과정에서 관련 기능을 직접 수정했으며, 발송 실패 처리와 24시간 미인증 신청 만료 등은 팀원이 후속 보완했습니다. 운영 Supabase의 전체 마이그레이션 실행 이력은 확인하지 않았습니다.
