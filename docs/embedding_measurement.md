> **이 문서의 위치**
> 선별은 세 단계다. 1차는 임베딩 9개를 관련 15건의 검색 점수로 6개까지 좁혔다. 2차는 후보 6개와 기준선을 같은 조건으로 놓고 30건의 검색 점수와 답변을 확인했다. 3차는 평가셋 v2 50건으로 최종 모델을 정한다. 이 문서의 v1 값은 최종 선택 근거가 아니다.

### 한계와 아직 재지 않은 것

- 관련 25건이라 95% 구간이 넓고 추천과 다른 상위 조합의 차이는 구별할 수 없다. 추천은 MRR 차이 0.008로 갈렸고 재측정 전후에 뒤집혔다.

## 11. 확정 조합 비교: voyage-4와 arctic-l-v2 (평가셋 v1 30건)

작성일 2026-11-03. 평가셋 v1(`evals/dataset_v1.jsonl`, sha256 `174996b9…`) 30건, 관련 15건, 비관련 15건의 값이다. 2026-11-03 팀장이 `voyage-4`, 영어 문장 벡터, 청크 800자·겹침 120자, 리랭커 없음에 질문 분해와 링크 확장 2개(L1x2)를 더한 조합으로 확정했다.

- **질문 분해:** 한 질문이 서로 다른 사실을 둘 이상 물으면 Haiku로 최대 3개의 하위 질문으로 나눠 각각 검색하고, 순위를 번갈아 합쳐 상위 5개를 만든다. 30건 중 11건이 나뉘었다(관련 9건, 비관련 2건).
- **L1x2:** 상위 5개 청크에 있는 핸드북 링크를 따라가 연결된 코퍼스 페이지의 청크 중 질문과 가장 비슷한 2개로 4·5위를 교체한다.
- **낙관 편향:** 두 규칙 모두 실패 문항을 본 뒤 추가했고 같은 30건으로 확인했다. L1x2의 근거는 7번 1문항이다. 새 문항 검증은 없다.
- **1문항의 크기:** 관련 1문항은 Recall@5 .067이다. 95% 구간이 겹치므로 점수 차이만으로 개선이라고 쓰지 않는다(가이드 p.17).
- **원자료:** `evals/results/retrieval_chunk_grid_v1/`, `evals/results/retrieval_fix_v1/`

| arctic-l-v2 하이브리드 + 리랭커 bge (후보 10) | 뺌 | 72조합 중 Recall@5 전체 1위 0.893(0.813~0.967), MRR 0.836. 리랭커 없음 0.773(MRR 0.733)보다 좋아진 문항 4(3, 7, 11, 33번), 나빠진 문항 없음, p 0.125라 4문항 차이를 개선이라 쓰지 않는다. 그래도 CPU p95 추정 7.2초로 3초와 5초 기준을 모두 넘어 채택하지 않았다. 리랭커가 점수를 올린 조합이 있었다는 사실은 숨기지 않는다 |
| arctic-l-v2 하이브리드 + 리랭커 bge int8 (후보 10) | 뺌 | Recall@5 0.853(0.733~0.960), MRR 0.808. 리랭커 없음보다 좋아짐 3(7, 11, 33번), 나빠짐 1(1번), p 0.625. CPU p95 추정 3.3초로 5초 안이지만 3초를 넘는다. 11.1의 1200/75 구성은 이 설정을 청크 크기만 바꾼 것이다 |

위 7개 행의 값은 평가셋 v2 관련 25건, 청크 800/120, k=5의 "전체 72조합" 표(10장)에서 옮겼고 좋아진 문항과 나빠진 문항은 `evals/results/retrieval_v2_round2/`와 `retrieval_v2_round2_clean/`의 문항별 결과로 직접 센 값이다. 시간은 부품 합 추정이다. v1 15건 값은 동결본 `evals/results/retrieval_v1_round1_frozen/compare.md`와 5, 6장 표에서 옮겼다. bge int8 값은 점수 저장 값 공유(`backend/rag/retrieve/retrieve.md` I-013) 때문에 v2는 재측정 값이고, v1의 int8 값은 다시 재지 않아 같은 영향이 있을 수 있다(`arctic-l-v2` 하이브리드 int8의 v1 15건은 동결 비교표 0.800, 72조합 표의 v1 15 열 0.833으로 다르다). 차이가 0~4문항이고 95% 구간이 모두 겹친다. 이 비교는 기본형(분해와 링크 확장 없음) 위의 전후이며 분해 + L1x2 위에 하이브리드나 리랭커를 얹은 조합은 재지 않았다.

### 11.10 한계와 아직 재지 않은 것

- 3번 정답 위치 `Release Day (Third Thursday)`는 찾지 못해 공식 Recall이 0.5다. 3회 모두 답은 맞고, 날짜는 정답으로 지정되지 않은 `GitLab Releases > Overview`를 인용했다. 동결 정답은 바꾸지 않았다.
- 3회 반복은 같은 검색 저장값으로 답변만 반복했다. 분해 판단은 저장값 1회다.
- 22번은 분해만, L1x2만, 분해 + L1x2의 상위 5가 같다. 분해만의 1회 실행에서 거절로 세지 않은 것은 규칙의 효과가 아니라 Haiku 실행 차이다. 거절 15/15가 다른 실행에서도 항상 유지된다고 말할 수 없다.
- 번역과 분해를 포함한 p95가 약 9.7초라, 답변 생성을 더하면 전체 p95 10초 기준을 넘을 가능성이 크다. 운영 경로는 재지 않았다.
- 하이브리드와 리랭커를 쓰지 않은 근거(11.9)는 기본형 위의 전후다. 확정한 분해 + L1x2 위에 하이브리드나 리랭커를 더한 조합은 재지 않았다.
- 평가셋 v2 50건, 단일 에이전트 그래프, RAGAS는 이 조합으로 재지 않았다. 그래프 값은 800/120 기본형만 있다(voyage-4 정답 근거 .867, 오답 근거 .929, 올바른 거절 1.000. arctic-l-v2 .900, .714, .933).
- 서비스 코드에 없는 것: 서비스 `embed.py`의 `voyage-4`(현재 `voyage-4-nano`만 있음), 질문 분해, 링크 확장, 링크 DB 칸(`chunks` 표), 링크로 가져온 청크의 `org`·`as_of` 필터. 평가 전용 측정 코드는 있다(`exp_decompose_v1.py`는 `voyage-4` 800/120의 기본형, L1x2, 분해, 분해 + L1x2를, `exp_answer_v1.py`는 Haiku 답변과 인용 집계를 다시 계산한다). 청크 12칸, `arctic-l-v2` 변형, 표 문장 보강, 시간 측정 코드는 저장소에 두지 않았고 원자료만 있다.
- 링크 확장은 강의자료에서 같은 방법을 찾지 못했다. 질문 분해는 LangGraph 19·20강의 비교 질문 예시를 비교 질문 외로 넓혔다.

### 11.11 확정 구성에 하이브리드·리랭킹이 없는 이유 한눈에 (F-18)

가이드는 개선 전후를 보이라고 했고(D3, p.15), 필수 스택 RAG 행은 하이브리드 검색과 리랭킹을 나열한다(p.10). 확정 구성(`voyage-4`, 영어 문장 벡터, 800/120, 분해 + L1x2)에는 둘 다 없다. 아래는 있는 쪽과 없는 쪽을 같은 평가셋 v2 관련 25건·청크 800/120·k=5에서 비교한 값이고, 모든 값은 이 문서 10장 "전체 72조합" 표의 줄에서 그대로 옮겼다(줄 번호는 이 파일). 11.9의 해당 행과 같은 값이다.

읽는 법.
- 확정 임베딩(`voyage-4`)에서는 하이브리드도 리랭커도 Recall@5를 올리지 못했다. 리랭커는 시간 추정만 0.7초에서 1.3~14.9초로 늘렸다. 문항별 좋아짐·나빠짐과 부호 검정 p는 11.9와 `EVAL_REPORT.md` 3-2에 있고 모두 p 1.0이라 "나빠졌다"고 단정하지 않는다.
- 리랭커가 실제로 점수를 올린 조합은 arctic-l-v2 하이브리드 + bge 하나다. 그 조합은 SPEC의 검색+리랭킹 p95 3초(와 사전 규칙 5초)를 CPU에서 넘어 채택하지 않았다. 숨기지 않고 표에 넣었다.
- 한계: 이 비교는 분해 + L1x2가 없는 기본형 위의 값이다(11.10의 "하이브리드와 리랭커를 쓰지 않은 근거" 항목). 확정 구성 위에 하이브리드·리랭커를 얹은 값은 재지 않았다. 시간은 부품 합 추정이고 관련 25건이라 구간이 넓다.
- 코드는 남아 있다: 하이브리드·리랭커 실험 코드와 전체 결과는 `evals/results/retrieval_v2_round2/`, `retrieval_v2_round2_clean/`에 있다.
