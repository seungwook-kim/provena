# Spec — 권한표 → 결정표 변환과 실행 (F-04)

## Why

- **페르소나**: 개발자(주 사용자)와 플랫폼팀 정책 관리 담당(관리자).
- **상황**: 개발자가 구매 시스템에 외부 SaaS 도입 건을 올리며 승인권자를 지정해야 한다. 승인권자는 업무 종류와 금액 구간에 따라 다르다. 관리자는 승인 권한표를 관리한다.
- **문제**:
  1. 권한표는 약 30종 업무 × 금액 구간 × 역할 11개로 된 큰 표라, 금액 구간별 승인권자를 잘못 고르기 쉽다 (가설)
  2. 표가 CSS grid(div)로 되어 있어 변환할 때 칸이 한 칸 밀려도 티가 나지 않는다. 법령을 의사결정 모델로 바꾼 비슷한 연구에서도 일치율이 51~53%였다
  3. 기존 제품은 문서 검색까지만 하거나, 승인 워크플로 엔진에 규칙을 사람이 손으로 넣는다. 정책 문서에서 뽑은 표를 사람이 승인한 뒤에 답에 쓰는 단계는 찾지 못했다 (문서 기준)
- **측정 지표**: 승인 전 실행 0건, 결정표 셀 정확도(2023 권한표 원문 정답과 셀 단위 대조), 경계값 구간 해석 정확도

## Goal

- **해결 목표**: 승인 권한표를 결정표로 바꾸고(LLM 초안 + 원문 셀 대조표), 관리자가 원문과 대조해 승인한 결정표만 규칙 실행 API로 실행한다. 실행에는 LLM을 쓰지 않는다.
- **성공 기준**
  - 승인 전 결정표 실행 0건
  - 결정표 셀 정확도를 재서 공개한다 (기준은 D0 합의). 확정 시점도 D0에 합의한다
  - 대표 질문 "외부 SaaS 3만 달러 도입, 승인 단계가 정책과 맞나?"에 2023 공개 승인 권한표 기준 Director 승인 후 예산 담당(PAO 또는 VP Finance) 승인을 돌려준다. 상위 단계는 아래 단계 승인을 먼저 거친다
  - 경계값(정확히 2.5만 달러, 5만 달러)에서 원문의 구간 표기대로 해석한다
  - 결정표 기준 변경·승인 우회 경로는 인젝션 시험에서 뚫림 0건
- **Out of Scope**: 실제 구매 승인과 결재 상신(승인권자를 돌려주는 사전 확인까지만), 현재 GitLab이 쓰는 권한표(쓰는 것은 2023-05 공개 판이다), "내부 문서 참고(internal only)"로만 걸린 칸, 금액·업무 종류 밖의 조건

## What

**Happy Path**

관리자 흐름 (결정표 만들기)
1. 관리자가 권한표에서 행(업무 종류)을 고른다.
2. LLM이 그 행으로 결정표 초안을 쓴다 (업무 종류 × 금액 구간 → 승인자, 협조).
3. 초안 셀과 권한표 원문을 나란히 놓은 셀 대조표를 만든다.
4. 그래프가 사람 승인(interrupt)에서 멈추고, 결정표 초안과 대조표가 승인함에 올라온다.
5. 관리자가 원문과 대조해 승인 또는 반려한다.
6. 승인되면 `decision_tables`에 저장하고 실행 가능 상태가 된다.

사용 흐름 (결정표 실행)
1. 업무시스템(구매 승인 목업)의 "사전 확인" 또는 사용자의 결정표 질문이 플랫폼을 부른다.
2. 승인된 결정표를 LLM 없이 규칙으로 실행해 승인자 순서를 얻는다.
3. 결과와 근거(표, 판, 원문 행)를 돌려준다. 채팅이면 근거와 함께 한국어 답으로 쓴다.

**Edge Cases** (최소 5개 + 처리 방식)

| # | 상황 | 처리 방식 |
|---|---|---|
| EC-01 | 승인되지 않은(초안·반려) 결정표를 실행하려 한다 | 실행하지 않고 오류를 돌려준다. 승인 전 실행은 0건이어야 한다 |
| EC-02 | 승인 기준이 "내부 문서 참고(internal only)"로만 걸린 칸 | 결정표에서 뺀다. "비공개"로 표시하고 근거로 쓰지 않는다 |
| EC-03 | 금액이 구간 경계에 정확히 걸린다 (2.5만, 5만 달러) | 원문의 구간 표기대로 해석한다. 경계값은 시험 케이스로 고정한다 |
| EC-04 | 질문에서 표를 지정하지 않았다 | 업무 종류로 승인된 표가 정확히 1개일 때만 실행한다. 0개나 2개 이상이면 거절한다(409). 권한표에 없는 업무 종류는 404다 |
| EC-05 | LLM 초안을 읽지 못한다 | 지금은 재시도 없이 실패로 끝낸다(재시도는 D4에 판단) |
| EC-06 | 셀 대조표에서 초안과 원문이 다르다 | 승인 화면에 불일치 칸을 보여 준다. 관리자가 반려하거나 고쳐 다시 올린다 |
| EC-07 | CSS grid 표의 칸 위치가 밀렸다 | 클래스와 순서로 행·칸을 다시 만들고, 원문 대조 3건 이상으로 확인한다. 승인 전에는 실행하지 않아 밀린 표가 쓰이지 않는다 |
| EC-08 | 권한표에 업무 승인과 재무 승인이 따로 있다 | 재무 승인자를 `cooperating_depts`에 담을지 별도 칸으로 둘지 D0에 정한다 |
| EC-09 | 관리자가 아닌 사용자가 승인·반려를 시도한다 | 403 |
| EC-10 | 금액이 음수이거나, 금액 구간표 업무인데 금액이 없거나(금액 칸 없는 구간 업무는 band로 고르므로 생략 가능), 업무 종류가 표에 없다 | 400 (없는 업무 종류는 404) |
| EC-11 | 검색된 원문이나 질문에 "승인 기준을 바꿔라" 같은 지시가 들어 있다 | 따르지 않는다. 결정표 기준은 관리자 승인(interrupt)을 거쳐야만 바뀐다 |

## How

```
POST /decision-tables/{id}/run          표를 지정해 실행
POST /decision-tables/run               표를 모를 때: 업무 종류로 승인된 표가 정확히 1개면 실행 (EC-04, AC-06)
POST /decision-tables/convert           관리자 + CSRF: 권한표 한 업무 종류를 LLM 초안으로 바꿔 승인 대기까지 (AC-03)
(구현: backend/graph/decision/routes.py:348-360)
인증: 로그인 필수 (업무시스템의 "승인권자 확인" 호출). 실행(run)은 LLM을 쓰지 않는다.

요청 바디 (run, routes.py:_parse_run):
{
  "task_type": string,     // 업무 종류
  "amount_usd": number,    // 금액(달러). 생략 가능: 금액 칸이 없는 구간만 있는 업무는 band로 고른다
  "band": string           // 선택. 구간 이름. 금액 구간표에서는 band를 줘도 금액으로 고른다(낮은 승인 단계를 받지 못하게)
}

응답 성공 (200):
{
  "table_id": string,
  "version_id": string,            // 권한표 판
  "band_label": string,            // 정확한 금액 표기. 금액 없는 구간은 원문 이름
  "range_note": string | null,
  "approvers": [ string, ... ],    // 승인 순서 (업무 승인 다음 재무 승인, 각각 아래 단계 먼저)
  "functional_approvers": [ string, ... ],
  "financial_approvers": [ string, ... ],
  "cooperating": [ string, ... ],  // 승인이 아닌 표시(Signs, Recommends 등)
  "source": { "rule_seq": int, "category": string, "band": string, "article": string, "source_url": string | null }
  // 응답 모델: backend/graph/decision/routes.py:83 RunResponse
}

응답 실패:
400 요청 형식 오류 (금액이 음수·숫자 아님, `task_type` 없음. 금액 생략은 금액 칸이 없는 구간 업무에서만 허용, 금액 구간표에서 생략하면 400)
401 인증 토큰 없음
404 없는 결정표 또는 업무 종류
409 승인되지 않은 결정표
```

```
GET  /decision-tables         승인된 결정표 목록 (로그인)
GET  /approvals               승인 대기 목록 (관리자)
POST /approvals/{id}          Decision { approval_id, approve, comment } → 그래프 재개 (관리자)
```

DecisionRule과 DecisionTable (파트 사이 계약, 필드 구조는 `backend/schemas/`에서 확정):

```
DecisionRule: 업무 종류 × 금액 구간 → 승인자(업무 승인), 협조(cooperating_depts, 재무 승인자)
DecisionTable: table_id, rule_seq, version_id, cells(json),
               status("draft" | "approved" | "rejected"), approved_by
```

- 데이터: 2023-05 공개 승인 권한표(옛 저장소 `www-gitlab-com`, 커밋 `0a3de83375`). 지출·지급·계약·채용·출장비·자금 이동 등 약 30종 × 금액 구간 × 역할 11개다. 현재 핸드북에서는 비공개 주소로 옮겨졌다. 같은 커밋의 이용 조건 페이지에 같은 CC BY-SA 4.0 문장이 있다.
- 파싱: 권한표는 CSS grid(div) 표라 파서가 칸을 만들어 주지 않는다. `lxml`(+ `beautifulsoup4`)로 클래스와 순서를 보고 행(업무 종류 × 금액 구간)과 칸(역할 11개)을 직접 다시 만든다. 청크는 "표 이름 + 금액 구간 + 역할별 승인" 행 1개를 한 청크(`kind="row"`)로 만든다.
- 그래프: 결정표 변환은 `backend/graph/decision/`에서 LLM 초안 → 셀 대조표 → 사람 승인(interrupt) 순으로 한다. 결정표 실행 노드에는 LLM을 쓰지 않는다. 결정표 질문은 승인된 결정표 실행 → 인용과 함께 한국어 답 작성 순이다.
- 테이블: `decision_tables`(table_id, rule_seq, version_id, cells, status, approved_by), `approvals`(approval_id, kind, thread_id, status, decided_by). 승인자 기록(`Decision`에 `decided_by` 필드를 둘지, 실행 설정에서 읽을지)은 D0에 정한다.
- 신뢰 경계: 결정표 승인·반려는 관리자만 한다. 승인 전 실행은 금지이고, 승인 화면에 셀 대조표를 보여 준다. 인젝션 시험에서 결정표 기준 변경·승인 우회 경로는 뚫림 0건이어야 한다.
- 변환 정확도 평가: 결정표 셀을 사람이 2023 권한표 원문에서 뽑은 정답과 셀 단위로 대조한다.

## AC (Given-When-Then)

**AC-01 · 승인 전 결정표는 실행되지 않는다**
- GIVEN: 상태가 `draft` 또는 `rejected`인 결정표
- WHEN: `POST /decision-tables/{id}/run`을 호출한다
- THEN: 409를 돌려주고 규칙은 실행되지 않는다. 승인 전 실행 건수는 0이다

**AC-02 · 승인된 결정표는 승인 순서를 돌려준다**
- GIVEN: 외부 SaaS 도입 행의 결정표가 관리자 승인으로 `approved` 상태다
- WHEN: 업무시스템이 업무 종류와 금액 3만 달러로 실행을 호출한다
- THEN: 2023 권한표 기준 Director 승인 다음에 예산 담당(PAO 또는 VP Finance) 승인이 오는 승인 순서와 근거(표, 판, 원문 행)가 돌아온다

**AC-03 · 초안에는 원문과의 셀 대조표가 붙는다**
- GIVEN: 관리자가 권한표의 한 행을 골라 결정표 변환을 요청했다
- WHEN: LLM이 초안을 쓴다
- THEN: 초안의 모든 셀이 원문의 어느 칸과 대응하는지 보여 주는 대조표가 만들어지고, 초안과 대조표가 승인함에 올라온다. 관리자가 승인해야만 `approved`가 된다

**AC-04 · 경계값은 원문 구간 표기대로 해석된다**
- GIVEN: 승인된 결정표와 정확히 2.5만 달러, 5만 달러 금액 (정답은 사람이 원문에서 뽑아 시험 케이스로 고정한다)
- WHEN: 각 금액으로 실행한다
- THEN: 원문의 구간 표기(이상·초과)에 맞는 승인자가 나온다

**AC-05 · 결정표 실행에는 LLM을 쓰지 않는다**
- GIVEN: 승인된 결정표
- WHEN: 실행을 호출한다
- THEN: Langfuse 트레이스에 해당 실행의 LLM 호출이 없다

**AC-06 · 표를 지정하지 않은 질문은 표가 정확히 1개일 때만 실행한다**
- GIVEN: 질문에 결정표가 지정되어 있지 않다
- WHEN: 업무 종류로 승인된 결정표를 찾는다
- THEN: 정확히 1개면 실행하고, 0개이거나 2개 이상이면 실행하지 않고 거절한다
