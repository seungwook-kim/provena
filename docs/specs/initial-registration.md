# 최초 로그인 5단계 등록

## Why

- **페르소나**: Provena에 처음 로그인한 일반 사용자·관리자·최고 관리자
- **상황**: 현재 회원정보 입력과 AI 기억 설정이 서로 다른 화면에 분리되어 있다.
- **문제**: 사용자가 등록 절차를 건너뛰거나, 기본 정보와 AI 기억의 저장 상태를 혼동할 수 있다.
- **측정 지표**: 미완료 사용자의 보호 화면 접근 0건, 단계 이동 시 입력값 유실 0건, 기본 정보 저장 실패 시 채팅 이동 0건

## Goal

- **해결 목표**: 팀·역할·서비스·기본 정보를 한 흐름의 5단계 화면에서 확인한 뒤 등록한다.
- **성공 기준**: 미완료 사용자는 직접 URL·새로고침·뒤로 가기로도 `/myinfo` 외 보호 화면을 렌더링하지 않으며, 최종 저장 성공 전 `/chat`으로 이동하지 않는다.
- **Out of Scope**: DB 스키마 변경, 새 AI 기억 저장소 구축, 관리자·승인·채팅 기능 변경

## What

**Happy Path**

1. 로그인 후 미완료 사용자는 1단계로 이동한다.
2. 소속 팀, 업무 역할, 담당 서비스, 이름·전화번호·주소를 입력한다.
3. 이전·다음 이동에서 입력값을 유지한다.
4. 5단계에서 전체 입력값을 확인하고 등록을 시도한다.
5. 기존 `/me/profile` 저장 성공 뒤에만 프로필 완료 상태를 다시 확인한다.

**Edge Cases**

| # | 상황 | 처리 방식 |
|---|---|---|
| EC-01 | 보호 화면 직접 접근 | `/myinfo`로 replace 이동 |
| EC-02 | 최종 기본 정보 저장 실패 | 현재 입력값 유지, 오류 표시, 채팅 이동 금지 |
| EC-03 | 전화번호 수정 | 기존 숫자 기반 자동 하이픈 처리 유지 |
| EC-04 | AI 기억 영구 API 미연결 | 등록 완료 처리 금지, 필요한 연동을 사용자에게 안내 |
| EC-05 | 브라우저 뒤로 가기 | 라우트 보호가 다시 `/myinfo`를 적용 |

## How

- **화면**: `web/react-app/src/pages/ProfileRequiredPage.jsx`
- **4단계 검증**: 이름은 trim 후 1자 이상, 전화번호는 숫자 기준 10~11자리, 근무지 주소는 선택 입력이다. 전화번호 placeholder는 값으로 취급하지 않는다.
- **보호**: `web/react-app/src/App.jsx`의 `Protected`와 인증 진입 라우트
- **기본 정보 저장**: 기존 `PUT /me/profile`과 `GET /me/profile?view=edit`, 완료 판정은 기존 `GET /me`
- **AI 기억**: 현재 `previewMemoryService`는 `sessionStorage`만 사용하므로 등록 완료 경로의 영구 저장 계약으로 사용하지 않는다.
- **제약**: `backend/schemas/`와 DB 스키마를 변경하지 않는다.

## AC

**AC-01 · 미완료 사용자 보호**

- GIVEN: 로그인 사용자의 `profile_completed`가 false
- WHEN: `/chat`, `/admin`, `/approvals`, 기타 보호 경로에 직접 접근
- THEN: 해당 화면을 렌더링하지 않고 `/myinfo`로 이동한다.

**AC-02 · 5단계 입력 유지**

- GIVEN: 1~4단계에 값을 입력함
- WHEN: 이전·다음 버튼으로 이동함
- THEN: 입력한 값이 유지되고 5단계에서 모두 표시된다.

**AC-03 · 저장 실패**

- GIVEN: 최종 등록 요청이 실패함
- WHEN: 사용자가 `등록 완료`를 누름
- THEN: 오류를 표시하고 현재 입력값을 유지하며 `/chat`으로 이동하지 않는다.

**AC-04 · AI 기억 영구 저장 미연결**

- GIVEN: AI 기억을 영구 저장할 서버 API가 없음
- WHEN: 사용자가 최종 등록을 시도함
- THEN: 임시 저장만으로 등록 완료 처리하지 않고 필요한 서버 연동을 안내한다.
