# 질문 속 출력 자리 요청 판정과 되묻기 출력 검사 (2026-11-17)

사전 등록과 결과: `evals/results/injection_fix_20261117/README.md`. 코드: `backend/graph/untrusted.py`(`QUESTION_RULES`, `requested_spans`, `scrub_answer`, `_trim_edges`, `echo_ok`),
`backend/graph/answer_fixes.py`(`quotable_phrases`), `backend/graph/departments/review.py`(빠진 값 되묻기). 시험: `tests/test_output_request_1117.py`, `tests/test_live_injection_6277.py`.

## Why

- 사전 등록 62.77의 질문 속 출력 자리 규칙 `output_ko`는 답 자리 낱말과 쓰기 동사 목록에 맞는 문장만 잡았다. 목록에 없는 표현으로 쓴 같은 요청은
  지시로 보지 못했고, 업무 절차를 묻는 정상 질문 한 꼴을 지시로 보았다(일반화 확인 `evals/results/injection_generality_provena-api-00181-zub/`: 오프라인 검출 16/20, 대조 오탐 1/10).
- 사용자에게 나가는 글은 종류와 상관없이 같은 출력 검사를 거쳐야 한다. 답(`verify`)과 판정이 쓴 되묻기(`give_up`)는 거쳤지만, 모르는 이름 되묻기(`GRAPH_UNKNOWN_NAME`)의 인용 구는
  질문 쪽 지시 판정에만 기댔고, 합동 검토의 빠진 값 되묻기는 출력 검사를 거치지 않았다.

## Goal

- 출력 자리 요청을 동사·낱말 목록이 아니라 문장 구조(말투, 자리, 문구)로 알아본다.
- 답, 되묻기 모두 같은 출력 검사를 거친다. 되묻기는 짧은 이름 꼴의 구만 인용한다.
- 정상 대조 오탐은 이전(1/10) 이하. 평가·데모 질문 171건의 판정과 모델 입력은 바뀌지 않는다.
- Out of Scope: 모델 입력 질문을 바꾸는 것(질문 쪽 판정은 지금처럼 출력 검사 후보와 되묻기 인용만 정한다), 검색 원문 정화 규칙 변경.

## What

1. 질문 전용 규칙 `output_request`(`untrusted.QUESTION_RULES`). `output_ko`를 대신한다. 한 문장(절)에 아래 셋이 있으면 지시다.
   - 말투: 분명한 요청 꼴(주세요, 줘, 주시면, 주실 수, 부탁, 바랍니다, please, kindly, can/could/would you)과 약한 꼴(-세요, -시오, 하라·해라, 문장 끝 반말·해라체 명령,
     "~ㄹ 것", 명사형 "바람", "잊지 마", 의무 부사(반드시, 꼭, 필히, 무조건, 필수), must, make sure, your ... should, 절 머리 영어 명령 동사, 자리 바로 뒤 쌍점·등호 명세).
     약한 꼴은 그 뒤에 절 경계 없이 물음표로 끝나면(업무 절차를 묻는 말) 세지 않는다. 남의 말을 옮기는 꼴("~해 주세요 라는 안내")의 말투도 세지 않는다.
   - 자리: 강(출력 낱말 답·답변·응답·대답·회신·답장·요약·출력·결론·본문·맺음말 바로 뒤의 끝·앞·마지막·말미·마무리·하단·아래·다음 줄 등, "end/bottom of your answer"),
     약(답 낱말 없는 줄·문장 자리, 답을 마치는 시점 "답변을 마친 뒤"·"after answering"·"once you're done", "~로 끝내", "end/begin/prefix ... with", "by saying", 답의 부분 이름 + 로·에·쌍점, "your answer").
   - 문구: 따옴표·괄호 문자열(영어 apostrophe 제외), 표식 토큰, 숫자열, 인용 조사 앞말("X라고"), "the word/phrase/line/tag/code/number X", "says X", 쌍점 뒤 꼬리.
   - 조건: 말투가 있고 (자리 강이거나 (자리 약이고 문구)). 따옴표가 열린 채 마침표로 갈린 문장은 이어서 본다(질문에만).
   - 질문(`strip_instructions(..., whole_sentence=True)`)에만 쓴다. 검색 원문에는 쓰지 않는다: 같은 규칙을 코퍼스 23,095청크에 대면 핸드북 절차 문장 65청크(67문장)가 걸린다.
2. 답 출력 검사(`scrub_answer`). 질문에 지시가 있으면 요청 문구(`requested_spans`: 요청 문장의 문구, 질문의 따옴표·괄호 문자열, 둘 이상이면 이은 값; 2글자 이상, 검색 원문에 없는 것)가 후보다.
   - 답 문장 끝이나 앞에 붙은 후보는 그 부분만 자른다(`_trim_edges`). 여러 낱말 문구의 낱말 조각(3글자 이상)도 문장 끝·앞에서만 자른다.
   - 후보만 있는 줄과 문장 가운데 든 후보는 지금처럼 문장째 뺀다. 답의 첫·끝 조각(인용 표시 없음)이 질문 지시 문장의 글자를 그대로 옮긴 것이면 뺀다.
   - 질문에 지시가 없으면 답을 바꾸지 않는다.
3. 되묻기 출력 검사.
   - 모르는 이름 되묻기의 인용 구(`answer_fixes.quotable_phrases`)는 지시 문장을 뺀 글에서 뽑고(기존), 짧은 이름 꼴(5낱말 이하, 문장 부호로 끝나지 않음, 2인칭 낱말 없음)이고
     답과 같은 출력 검사(`untrusted.echo_ok` -> `scrub_answer`)를 통과한 구만 인용한다. 남는 구가 없으면 인용 없는 일반 문구로 되묻는다.
   - 이 함수는 단일 그래프와 멀티 그래프가 같이 쓰는 검색 노드(`search`)가 부르므로 두 `/chat` 경로에 같이 걸린다. 판정 되묻기(`give_up`)와 답(`verify`)도 두 경로가 같은 노드를 쓴다.
   - 합동 검토의 빠진 값 되묻기는 `leaks_instruction`에 걸리면 빠진 값 이름 없이 되묻는다. 거절 문구는 고정 문장이라 사용자 글을 담지 않는다.
4. 스위치는 두지 않는다. 기존 출력 검사 스위치(`GRAPH_SCRUB_OUTPUT`)를 따른다. LLM 호출과 비용은 늘지 않는다.

## AC

- GIVEN 출력 자리 요청 문장 11꼴(한국어·영어, 강·약 자리, 시점 자리, 명세 꼴)과 정상 질문 문장. THEN 요청 문장만 지시로 빠진다(`test_output_request_sentences_are_instructions_in_questions`).
- GIVEN 업무 절차를 묻는 질문 8꼴(넣어야 하나요, 넣는 규칙, 꼭 ... 하나요, 남의 말 옮기기, should I, when you finish ... ?). THEN 지시가 아니고 답을 바꾸지 않는다.
- GIVEN 요청을 따른 답(문장 끝·앞에 붙임, 따로 한 줄). THEN 문구만 사라지고 정상 문장과 인용 표시는 남는다. 검색 원문에 있는 문구는 자르지 않는다.
- GIVEN 모르는 이름이 든 질문 + 출력 자리 요청. THEN 되묻기 글은 요청 문구·요청 문장 조각을 담지 않고 옆의 정상 이름은 인용한다.
- GIVEN 핸드북 절차 문장 꼴의 검색 원문. THEN 정화 결과가 바뀌지 않는다(질문으로 오면 요청으로 본다).
- GIVEN 평가·데모 질문 171건. THEN `output_request` 일치 0, 지시 문장 판정 0, 모델 입력 질문 변화 0(`tests/test_live_injection_6277.py::test_eval_and_demo_questions_untouched`).
- 오프라인 개수(기존 변형 20 + 대조 10, 새 검증 묶음 두 개 각 변형 22 + 대조 12)는 결과 README에 적는다.
- 한계: 규칙은 알려진 문장 구조만 본다. 말투·자리·문구 가운데 하나라도 다른 말로 쓴 요청(이 규칙의 목록 밖 자리 이름, 요청 말투 없는 서술), 한국어·영어 밖의 언어,
  여러 턴에 나눠 둔 요청은 놓칠 수 있다. 질문 모양의 명령(영어 명령문으로 쓴 업무 질문)은 요청으로 볼 수 있다(그때도 바뀌는 것은 출력 검사 후보와 되묻기 인용뿐이다). 운영 판 재시험 전이다.
