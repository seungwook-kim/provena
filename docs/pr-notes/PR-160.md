- 고친 것 [코드]: `backend/services/demo_replay.py`에 후보 자리(`_lane` 문맥 변수, `in_lane`)를 더했다. `ReplayStore.pick_ranked(key, run=, lane=)`는 자리가 있으면 차례를 그 자리 안에서 따로 세고 `lane`번 변형부터 낸다(첫 후보는 늘 0번, 둘째 후보는 늘 1번 변형부터). `backend/graph/build.py`의 `as_candidate`가 재생 모델일 때만(`replay_demo()`) 두 후보에 자리 0, 1을 붙인다(`judge`의 두 후보, `write_answer`의 두 후보, 4곳). 그래프를 고친 이유: 재생 쪽에서는 호출이 어느 후보의 것인지 알 수 없다(두 후보의 스레드 이름, 실행 문맥, 요청 키가 모두 같다). `STAGGER_S`는 그대로다(늦춤을 키우지 않았다).
- 운영 동작 [코드, 실측]: 실제 모델이면 `as_candidate`가 넘겨받은 함수를 그대로 돌려줘 호출 수, 순서, 지연, 답 고르기 규칙이 그대로다. 자리 값은 재생 모델만 읽는다. 재생 모델이 아닌 가짜 모델로 그래프를 돌리면 자리가 붙지 않는 것을 시험이 본다.
