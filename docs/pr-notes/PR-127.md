- 화면과 API가 같은 주소라 새로고침 때 받은 HTML이 브라우저 캐시에 남아 JSON 검사에서 실패했다 → 캐시 금지 헤더. 근거: 커밋 `b2ead52`·`1b77371` 메시지.
- 운영 DB에 113·114가 없어도 로그인·가입·승인이 503이 되지 않게, 저장소가 칸 존재를 먼저 확인한다(`backend/services/auth_store.py`). 근거: 커밋 `bc0ced0` 메시지, 107·108만 적용한 DB로 직접 확인(`tests/test_auth_schema_compat.py`).
- 미인증 신청 즉시 덮어쓰기는 비밀번호 바꿔치기로 계정을 가로챌 수 있어 빼고, main의 24시간 규칙(`STALE_UNVERIFIED_SIGNUP_HOURS`, `auth_store.py:85`)을 되살렸다. 근거: 커밋 `f9b95f3` 메시지.
- 번호(request_id)로 승인·거절하면 그 행만 `FOR UPDATE`로 잠근다. 같은 이메일에 거절 행과 새 신청이 함께 있을 때 가장 최근 신청이 처리되던 문제 때문. 근거: 커밋 `1d08fc3` 메시지.
- SQL 번호는 파트별(100번대 = 인증, `db/db.md`)이라 Google 연결 SQL을 203 → 114로, 가입 모서리를 112 → 113으로 바꿨다(조장 PR #126의 `112_approval_resume_log`와 겹침). 근거: 커밋 `7c26a38`·`b21be48` 메시지.
