# 대체재 비교 근거 (범용 챗봇 답)

평가 리포트(`EVAL_REPORT.md`) 10장 "대체재와의 비교"의 표가 기대는 원자료입니다. 같은 질문 10개(1~5번, 6~10번)를 범용 챗봇 2종에 넣어 받은 답을 그대로 둡니다. 수집은 2026-11-10과 2026-11-11에 팀장이 직접 했습니다.

| 파일 | 내용 | 원문 여부 |
|---|---|---|
| `prompts.md` | 입력한 질문 10개와 입력 조건 | 질문 원문 |
| `chatbot_a_2026-11-11.md` | 챗봇 A(ChatGPT 웹)의 1~5번 답, 새 대화창, 웹 검색 사용 | 답 전문. 10장의 A 열(1~5번)은 이 파일로 판정 |
| `chatbot_a_2026-11-10.md` | 챗봇 A의 첫 수집(2026-11-10) | 챗봇이 답 끝에 낸 요약과 덧붙임 문단뿐. 판정에 쓰지 않음 |
| `chatbot_b_2026-11-10.md` | 챗봇 B(Claude Haiku 5.5)의 1~5번 답 | 답 전문 |
| `chatbot_a_2026-11-11_q6-10.md` | 챗봇 A의 6~10번 답, 새 대화창, 웹 검색 사용 | 답 전문 |
| `chatbot_b_2026-11-11_q6-10.md` | 챗봇 B의 6~10번 답, 새 Haiku 에이전트, 웹 검색 사용 | 답 전문 |

우리 서비스의 답은 10장에서 1~5번에 리비전 `provena-api-00035-h69`의 측정 행을 썼습니다. 위치는 `evals/results/deploy_latency_provena-api-00035-h69/run1~3/rows.jsonl`(v2 6, 15, 28, 16번)과 `evals/results/deploy_latency_holdout_provena-api-00035-h69/run1~3/rows.jsonl`(검증 109번)의 `answer` 칸입니다. 6~10번은 최종 배포 뒤 운영 측정의 3회 값에서 가져오며, 위치는 `evals/results/deploy_latency_<리비전>/run1~3/rows.jsonl`(v2 40, 3, 31번)과 `evals/results/range_retrieval_62_7/answers_deploy_<리비전>/`(금액 201, 202번)입니다. 리비전은 측정 뒤 적습니다.

## 한계

- 챗봇 A와 B 모두 10장의 판정은 답 전문으로 했습니다(1~5번의 A는 2026-11-11, B는 2026-11-10 전문이고 6~10번은 둘 다 2026-11-11 전문). 챗봇 A의 출처는 문서 이름 수준이고 링크는 옮겨 오지 않아, 링크의 실재는 확인하지 못했습니다.
- 질문 5개씩 두 묶음을 각각 한 대화에 한꺼번에 넣었습니다. 우리 서비스는 문항마다 새 대화입니다.
- 6~10번과 챗봇 A의 1~5번 재수집에는 "근거나 출처가 있으면 함께" 머리말이 있고, 챗봇 B의 1~5번에는 없습니다(`prompts.md`).
- 챗봇 A는 11/10 수집(요약만)과 11/11 수집(전문)의 입력 시점이 다릅니다. 같은 날 이전 맥락이 남은 창에서 받은 답은 비교에 쓰지 않았습니다.
- 6~10번은 문항마다 한 번씩만 수집했습니다.
- 챗봇 B의 1, 2, 5번은 웹 검색 없이 받은 답입니다(B는 3번만 검색을 썼습니다). 이 세 문항은 검색을 쓴 챗봇 A, 우리 서비스와 같은 조건이 아닙니다.
- 화면 캡처와 대화 링크는 남기지 않았습니다.
- 판정은 문서 작성 쪽에서 한 가안입니다. 제2 확인자: 박진형. 재확인 기록: 제2 확인자 박진형, 2026-11-12, 60칸(질문 10개 x 챗봇 2종 x 3항목) 중 2칸 변경(챗봇 A 7번과 8번의 정답 여부). 변경 내용은 "승인자 특정 못 함"에서 오답으로 바꿈(정답지에 없는 승인자 FP&A를 적음, `EVAL_REPORT.md` 10-4절 1번). 나머지 칸(질문 10개 x 챗봇 2종의 정답 여부, 출처 제시, 판 날짜 언급)은 가안과 같음
