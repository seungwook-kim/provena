5. 데이터팀 dbt 모델 SQL에서 서브쿼리를 써도 되나? 팀 스타일 가이드는?
서브쿼리 사용이 문법적으로 불가능한 것은 아니지만, GitLab 데이터팀의 SQL 스타일 가이드는 CTE(Common Table Expression) 사용을 권장합니다.

즉, 서브쿼리보다는 WITH 절을 사용해 쿼리를 논리적인 단위로 분리하는 것이 권장됩니다.

권장 방식: CTE 사용
WITH important_list AS (

    SELECT DISTINCT
        specific_column
    FROM other_table
    WHERE specific_column != 'foo'

)

SELECT
    primary_table.column_1,
    primary_table.column_2
FROM primary_table
INNER JOIN important_list
    ON primary_table.column_3 = important_list.specific_column


비권장 방식: 서브쿼리 사용
SELECT
    primary_table.column_1,
    primary_table.column_2
FROM primary_table
WHERE primary_table.column_3 IN (
    SELECT DISTINCT specific_column
    FROM other_table
    WHERE specific_column != 'foo'
)


팀 스타일 가이드의 주요 권장 사항
항목    권장 사항
쿼리 구조    서브쿼리보다 CTE 사용
CTE 위치    쿼리 최상단
CTE 역할    하나의 논리적 작업 단위로 구성
CTE 이름    간결하면서 의미가 명확하게 작성
CTE 중복    여러 모델에서 반복되면 별도 dbt 모델로 분리
키워드    SQL 키워드, 데이터 타입, 함수는 대문자
들여쓰기    공백 2칸
테이블 별칭    최소 4자
GROUP BY    명시적 컬럼 또는 위치 기반 참조 권장, GROUP BY ALL 지양

또한 SQLFluff를 이용한 린팅과 코드 리뷰를 통해 스타일을 관리합니다.
